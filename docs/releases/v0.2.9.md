## What's new

- **WiFi joystick: a channel count setting, and a new rate or count reaches a streaming module.** Web page →
  Sticks: **Packet interval** (`wifi_interval_us`, 4000 = 250 Hz, the default; the box now suggests 1000 Hz
  down to 50 Hz) and the new **Channel count** (`wifi_channels`, 4-16, default 16). An ELRS module only takes a
  new rate or count when its stream starts, so a change saved while it streams now stops its stream and starts
  it again (the sticks pause for a moment). Before, a new packet interval reached the module only at its next
  start. Fewer channels leave the higher ones empty: keep the pause switch and the stick mapping within them.
- The restart goes out at once when the module surely is ELRS (its broadcast was seen, or it sends other than
  16 channels). A module that sends 16 channels and whose broadcast the Pi hasn't seen may be Crossfire: the Pi
  first waits up to 20 s for a Crossfire broadcast. A restart counts only when the module accepted both the stop
  and the start (an answer with an error doesn't count). Else, while the module keeps streaming, the Pi tries
  the stop and start 3 times in all, 5 s apart, then says in the log (System → Log) that it gave up. If the
  stream stops first, the Pi restarts the module once more when its stream is back.
- **Crossfire** always sends 16 channels about 90 times a second: these settings don't change it, and the Pi
  never stops the stream of a module it knows as Crossfire by its broadcast (the log says so once). If
  broadcasts can't reach the Pi (`wifi_module_ip` set because the router blocks them), it can't tell Crossfire
  from ELRS: after 20 s it treats the module as ELRS, so a change of these settings, or a Channel count below
  16, then sends the Crossfire module the stop and the start too.
- A module still streaming what another app asked for (the PC app, another Pi) is restarted once with your
  values when it sends another channel count. A different rate alone is kept: switch the module's WiFi off and
  on, or save a new value on the web page, to get yours.
- **The same WiFi joystick code as the Linux app.** The protocol part is now shared with ExpressLRS / TBS
  Crossfire WiFi Joystick for Linux 1.0.0, and the Windows app follows the same rules from version 3.3.
  Unchanged: in flight the game pauses 0.5 s after the WiFi sticks stop, and the Pi lets go of the module after
  3 s.
- `wifi_module_ip` no longer takes 0.0.0.0 (it names no module).

## Update from the web page

From 0.2.1 or newer: Updates → Check → install StickTime Pi 0.2.9. The game stays at StickTime 1.9.0. Your
settings stay as they are: Packet interval keeps your value, Channel count starts at 16 (what the Pi always
asked for).
