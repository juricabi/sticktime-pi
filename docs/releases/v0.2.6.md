## What's new

- **Interlaced without the flicker.** The new flicker filter (web page → Video → Flicker filter,
  `av_flicker`) blends each line with the lines above and below it, so a thin line or text lands in both
  fields of 480i / 576i and stops flickering. **Full** (the default) stops it completely at a little vertical
  softness, as a GameCube does in 480i; **Light** keeps more detail; **Off** is interlaced as before. It also
  softens the picture's top and bottom edges into the border.
- **Picture detail for interlaced too.** `av_detail = high` (the default) now also draws interlaced 480i /
  576i with twice the lines and twice the width: the flicker filter averages the line pairs on the way out
  and the display scales the width. The smoothest picture StickTime Pi makes, and the most work (four times
  the pixels of progressive): on NTSC a Pi 4 holds 60 fps in most views with Drawing on Multi-core, the
  heaviest (the menu's dark overlay, dense tracks) can dip; PAL draws a fifth more pixels. It runs the Pi warm
  (close to the 80 °C where it slows itself down): give it a heatsink or a small fan, or set Picture detail to
  Normal. A card from 0.2.5 on interlaced has `av_detail = high` in its settings already, so it gets this
  with the update.
- **Lines keep their weight at double detail.** The game draws 1 pixel lines (the floor grid, outlines); at
  double detail they used to fade to a quarter when scaled down. They are now drawn 2 pixels wide there.
- **Drawing on several cores** (web page → Video → Drawing; it switches at once):
  - **Multi-core** (the default) draws each frame on three of the Pi's four cores, the fourth left to the
    sound: exactly the same picture as one core, in about half the time (double detail on a Pi 4: the menu
    18 → 9 ms a frame, a flight 7.5 → 4.3 ms). On interlaced composite each band of the frame also makes
    its part of the copy out through the flicker filter while it is still in the CPU's cache.
  - **GPU** draws on the graphics chip (OpenGL ES 2, for the Pi 3, 4 and 5; a new helper program,
    `bin/sticktime-gpu`). It frees the cores, but on a Pi 4 it is slower than
    Multi-core at double detail, and edges may differ by a pixel. When it can't start it draws on the cores.
  - **One core** is how 0.2.5 drew.
- **Faster drawing everywhere**: blending without division, in code the compiler turns into vector
  instructions; level lines drawn as runs; the frame drawn in bands small enough for the CPU's cache.
- **Restart doesn't hang any more.** The web page's Restart, and settings that need a restart, start the game
  again at once. Before, each restart in a boot waited longer than the last (up to 30 s of black, which
  looked like a hang).
- **Status page: where the latency comes from.** Frame times shows the wait for the refresh with its safety
  margin, and a note says how latency adds up: the game, the copy, the wait (with the screen's blanking gap
  between two pictures) and half a refresh while the picture goes out line by line. The user guide explains
  it ("Latency and frame times"). `GET /api/status` has the parts (`wait_ms`, `margin_ms`, `budget_ms`,
  `event_lag_ms`, `late_on_time`).
- **Bluetooth off is said on the page.** With `bluetooth = off` the Sticks page says that no Bluetooth device
  can connect (the ELRS BLE joystick, gamepads, keyboards), and warns when the stick source is Bluetooth.
- The Game page's Script card says when a switch of editions happens: with StickTime (color) in the game's
  main menu, with the BW and Lite editions at once.
- A Pi with fewer working cores (`maxcpus=` in cmdline.txt) gets a fitting share of them; the game's loop
  goes to the last core when it has no core 3.

## Update from the web page

From 0.2.1 or newer: Updates → Check → install StickTime Pi 0.2.6. The game stays at StickTime 1.9.0.

From 0.1.0 or 0.2.0: those updaters can't install updates (see the 0.2.1 notes): flash this image once.
Copy `sticktime.txt`, `sticktime/music` and, from `sticktime/sd/SCRIPTS/TOOLS`, `StickTime.dat`,
`StickTimeBW.dat`, `StickTimeLite/data.txt`, `StickTimeTracks` and `StickTimeGhosts` to your PC first, and
put them back after flashing (the WiFi password isn't in `sticktime.txt` any more after a boot: type it
again).
